# Spec 08 — Internacionalización (i18n)
> Markify — Arquitectura i18n completa con JSONs de traducción para ES y EN.
> Archivos destino: `src/i18n/`
> Dependencias: spec `01-types.md` (tipos Language/ResolvedLanguage)

---

## 1. Arquitectura

- **Librería:** `react-i18next` + `i18next-browser-languagedetector`
- **Idiomas soportados:** `en` (inglés) y `es` (español)
- **Detección:** automática por `navigator.language` del OS al primer arranque
- **Persistencia:** la elección manual del usuario se guarda en `useAppStore` (Tauri Store)
- **Namespaces:** `common` (textos de UI) y `messages` (mensajes de error del sidecar)
- **Variantes regionales:** `es-MX`, `es-CO`, `es-AR` → mapeadas a `es`. `en-US`, `en-GB` → mapeadas a `en`
- **Fallback:** si el idioma del OS no es `es` ni variante de `es`, usar `en`

---

## 2. Configuración (`src/i18n/index.ts`)

```typescript
import i18n from 'i18next';
import { initReactI18next } from 'react-i18next';
import LanguageDetector from 'i18next-browser-languagedetector';

// Importar todos los JSONs
import enCommon from './locales/en/common.json';
import enMessages from './locales/en/messages.json';
import esCommon from './locales/es/common.json';
import esMessages from './locales/es/messages.json';

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    // Idioma por defecto si la detección falla
    fallbackLng: 'en',

    // Solo soportar estos dos
    supportedLngs: ['en', 'es'],

    // Cargar solo el idioma base, no variantes ('es' en lugar de 'es-CO')
    load: 'languageOnly',

    // Configuración del detector
    detection: {
      // Orden: primero localStorage (guardado por el usuario), luego el navegador
      order: ['localStorage', 'navigator'],
      caches: ['localStorage'],
      lookupLocalStorage: 'markify-i18n-language',
    },

    // Namespaces disponibles
    ns: ['common', 'messages'],
    defaultNS: 'common',

    // Recursos embebidos (no lazy-loading — la app es offline)
    resources: {
      en: {
        common:   enCommon,
        messages: enMessages,
      },
      es: {
        common:   esCommon,
        messages: esMessages,
      },
    },

    interpolation: {
      escapeValue: false, // React ya escapa por defecto
    },
  });

export default i18n;
```

**Importar en `src/main.tsx`:**
```typescript
import './i18n/index'; // Antes de renderizar la app
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';
import './index.css';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);
```

## 3. Uso en componentes

```typescript
// En cualquier componente:
import { useTranslation } from 'react-i18next';

function MyComponent() {
  const { t } = useTranslation(); // namespace 'common' por defecto

  // Sin interpolación
  t('dropzone.title')

  // Con interpolación
  t('processing.progress', { completed: 2, total: 5 })

  // Pluralización
  t('results.successAll', { count: 3 })
  // → usa 'results.successAll_one' cuando count === 1
  // → usa 'results.successAll_other' cuando count !== 1

  // Namespace 'messages' (errores del sidecar)
  const { t: tm } = useTranslation('messages');
  tm('conversion.password_protected')
}
```

**Cambiar idioma programáticamente** (desde `LanguageToggle`):
```typescript
import i18n from '@/i18n';
await i18n.changeLanguage('es');
// También actualizar el store para persistencia:
await useAppStore.getState().setLanguage('es');
```

## 8. Reglas de pluralización

`react-i18next` usa el estándar CLDR para plurales. Para español e inglés, las formas son `_one` y `_other`:

```json
// Para count === 1:
"successAll_one": "1 archivo convertido correctamente"

// Para count !== 1:
"successAll_other": "{{count}} archivos convertidos correctamente"
```

Uso en componente:
```typescript
t('results.successAll', { count: summary.completed })
// count=1 → "1 archivo convertido correctamente"
// count=3 → "3 archivos convertidos correctamente"
```

## 9. Idioma del sidecar Python

El sidecar recibe el idioma al iniciar una conversión (campo `lang` en el payload del comando `convert`). El sidecar usa ese valor para seleccionar los mensajes de error en `error_messages.py`.

El frontend debe pasar el `resolvedLanguage` actual del store:

```typescript
// En useConversionStore.startConversion():
const lang = useAppStore.getState().resolvedLanguage;
await tauriCommands.startConversion({ files: [...], lang });
```
